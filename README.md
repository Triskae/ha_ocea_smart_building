# Ocea Smart Building - Home Assistant Integration

[![hacs][hacs-badge]][hacs-url]
[![release][release-badge]][release-url]
![downloads][downloads-badge]

Home Assistant integration to monitor water and heating consumption from the [Ocea Smart Building](https://espace-resident.ocea-sb.com) resident portal.

## Features

- **Cold water** consumption in m³
- **Hot water** consumption in m³
- **CETC heating** consumption in kWh when available for the dwelling
- Precise monthly cold-water, hot-water, and CETC heating totals
- Latest Ocea leak estimates for cold and hot water
- Automatic one-time import of all available daily history into Recorder
- Compatible with the **Energy dashboard** (water and energy sections)
- Automatic Azure AD B2C authentication (no headless browser needed)
- Automatic token refresh
- UI-based configuration
- Native Home Assistant reconfiguration for the email and password
- Validates every dwelling returned by Ocea and skips stale or forbidden
  occupations instead of failing on the first one

## Installation

### Via HACS (recommended)

[![Open your Home Assistant instance and open this repository in HACS](https://my.home-assistant.io/badges/hacs_repository.svg)](https://my.home-assistant.io/redirect/hacs_repository/?owner=Triskae&repository=ha_ocea_smart_building&category=integration)

1. HACS → Integrations → ⋮ → Custom repositories
2. Add the repository URL, category **Integration**
3. Search for "Ocea Smart Building" → Install
4. Restart Home Assistant

### Manual

Copy `custom_components/ocea_smart_building/` into `config/custom_components/` and restart Home Assistant.

## Configuration

[![Open your Home Assistant instance and add the integration](https://my.home-assistant.io/badges/config_flow_start.svg)](https://my.home-assistant.io/redirect/config_flow_start/?domain=ocea_smart_building)

Settings → Devices & Services → Add Integration → "Ocea Smart Building"

- **Email**: your Ocea resident portal email
- **Password**: your Ocea password

Your dwelling is automatically detected from your Ocea account.

When an account contains several occupations, the integration verifies access
to each dwelling dashboard and stores the first accessible identifier. During
reauthentication or reconfiguration, the currently configured dwelling is tried
first. If Ocea later returns HTTP 403 for that dwelling, Home Assistant starts
its normal reauthentication flow so another accessible occupation can be
selected without exposing the dwelling identifier in the form.

### Reconfiguration

Open Settings → Devices & Services → Ocea Smart Building, then select the native **Reconfigure** action.

- The current email address is prefilled and can be changed.
- The stored password is never displayed. Leave the password field unchanged to keep it, or enter a new password to replace it.
- Credentials are validated with Ocea before changes are saved.
- Home Assistant reloads the integration only when the validated configuration has actually changed.

## Energy dashboard

Add the cold and hot water sensors in Settings → Dashboards → Energy → Water consumption. When available, the CETC heating sensor can also be added as an energy-consumption source.

### Standard and precise sensors

The integration exposes two variants for cold water, hot water, and CETC
heating:

| Standard sensor | Precise sensor |
| --- | --- |
| Uses Ocea's `dashboard/consos` endpoint | Uses the detailed `conso/{fluid}` endpoint |
| Returns the total already aggregated and rounded by Ocea | Recalculates the current-month total from daily values |
| Intended for comparison with the Ocea resident dashboard | Recommended for graphs, long-term statistics, and the Energy dashboard |

The precise water sensors display three decimal places. For water,
`0.001 m³` equals one litre, so they avoid losing several litres through the
dashboard endpoint's coarser rounding. The precise CETC sensor applies the same
daily aggregation to heating consumption in kWh.

Precise sensor states represent the current calendar month and therefore reset
when a new month starts. Their `total_increasing` state class allows Home
Assistant Recorder to maintain a continuous long-term sum across those resets.
The one-time history import described below is attached to these precise
sensors. Standard sensors remain available as a direct comparison with the
values shown in the Ocea portal.

### Sensors created by the integration

Entity IDs are generated by Home Assistant from the device and sensor names, so
the exact prefix may vary. The suffixes below identify each sensor reliably.

| Sensor | Typical entity-ID suffix | Unit | Availability and recommended use |
| --- | --- | --- | --- |
| Cold water | `_eau_froide` | m³ | Standard portal value; useful for comparison with Ocea |
| Hot water | `_eau_chaude` | m³ | Standard portal value; useful for comparison with Ocea |
| CETC heating | `_cetc` | kWh | Created when the dwelling exposes CETC heating |
| Precise cold water | `_eau_froide_precise` | m³ | Recommended for graphs, statistics, and the Energy dashboard |
| Precise hot water | `_eau_chaude_precise` | m³ | Recommended for graphs, statistics, and the Energy dashboard |
| Precise CETC heating | `_cetc_precise` | kWh | Created when CETC data is available; recommended for long-term statistics |
| Estimated cold-water leak | `_fuite_eau_froide` | m³ | Created only when Ocea returns `fuiteEstimee` for cold water |
| Estimated hot-water leak | `_fuite_eau_chaude` | m³ | Created only when Ocea returns `fuiteEstimee` for hot water |

Ocea consumption data is generally not real time. The newest value usually
corresponds to the previous day, and meter collection or Ocea processing may
occasionally delay it by several days. The integration automatically includes
late values as soon as the API publishes them; a missing value for the current
day does not by itself indicate an integration failure.

### Historical data

On first setup, the integration retrieves the complete daily history available
from Ocea in a background task. The import fills long-term statistics for the
precise cold-water, hot-water, and heating sensors. Home Assistant startup is not
blocked by the import, and a failed import is retried on the next reload.

The API is queried one calendar year at a time, newest first. Once data has been
found, two consecutive empty years stop the search. This avoids dozens of empty
requests for recent dwellings while retaining the complete contiguous history.

### Leak estimates

When Ocea provides `fuiteEstimee` in its detailed daily response, the integration
creates cold- and hot-water leak-estimate sensors. These entities are omitted
when the API does not provide a leak estimate for the dwelling.

## Troubleshooting

Before investigating a missing current-day value, check the latest date shown in
the Ocea resident portal. A one-day delay is normal, and longer delays can occur
upstream of Home Assistant. Authentication failures, repeated update errors, or
data missing from both the portal and Home Assistant should be investigated
separately.
